FINAL: Adapting huge models on a single GPU is made affordable primarily through techniques that minimize memory consumption by freezing the base model and training only a small fraction of parameters. Based on the retrieved information, the key methods include:

*   **Low-Rank Adaptation (LoRA):** This method freezes the pretrained model weights and injects small, trainable low-rank matrices into the layers. By learning only these low-rank updates, the number of trainable parameters is drastically reduced, avoiding the need to store a full-size copy of the model for every task.
*   **QLoRA:** An extension of LoRA that further reduces memory requirements by quantizing the base model to a 4-bit format (NormalFloat4). The base model remains frozen in this compressed state, and gradients flow only through the tiny, trainable adapter matrices, allowing for the fine-tuning of massive models on consumer-grade hardware.
*   **Adapter Tuning:** This approach inserts small, bottleneck-style modules between the existing layers of a frozen Transformer. These modules project hidden representations into a lower dimension and back, allowing the model to adapt to new tasks while keeping the vast majority of the original parameters static.
*   **Prompt Tuning:** This method simplifies adaptation by prepending a small set of learnable "soft prompt" embeddings to the model's input. By keeping the entire model frozen and only updating these input embeddings via backpropagation, it avoids the memory overhead associated with updating internal model weights.
*   **In-Context Learning:** As demonstrated by GPT-3, this approach avoids weight updates entirely. Instead of fine-tuning, the model is provided with task descriptions and a few examples directly within the prompt, allowing it to perform tasks without modifying its internal parameters.
*   **Knowledge Distillation:** While not a direct fine-tuning method, this technique transfers the knowledge from a large, memory-hungry "teacher" model into a smaller, more compact "student" network. This allows for the deployment of high-performing models that are significantly cheaper to run on limited hardware.
